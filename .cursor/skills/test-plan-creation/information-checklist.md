# テスト計画書 — 必要情報チェックリスト

エージェントは各項目を **確定 / 一部 / 未** で棚卸しする。未決は `決定が必要な項目.md` へ、確認依頼は `確認事項一覧.md` へ逃がす。

**優先度**

- **P0**: これが無いと計画書の骨格が立たない
- **P1**: ドラフトの実用性に直結
- **P2**: 後追いでよい（`【要確認】` 可）

---

## ヘッダー・メタ情報

| 項目 | 優先 | 例・形式 | 未決時の扱い |
| --- | --- | --- | --- |
| テスト計画書識別番号 | P2 | `TP-PROJ-001` | 仮番号または `【要採番】` |
| 対象システム名 | P0 | KJDD（キングジム向けシステム） | ユーザーに確認 |
| バージョン | P1 | `v1.0` 起票、改訂でインクリメント | 初回は `v0.1` ドラフト可 |

| 作成者・担当者の記載方針 | P1 | 実名記載 / 役割のみ / 記載しない | プロジェクト方針として §5 と整合 |

## 壁打ちシナリオ例

### 新規プロジェクト（何も無い）

1. P0: システム境界・フェーズ・スコープ内外  
2. P0: 品質方針（数値目標 vs カバレッジ可視化）  
3. P1: 自動化範囲・リリース判定  
4. Phase B: §1〜§4 のドラフト  
5. P2: 環境・リスク・スケジュール追記  

### 既存計画の改訂（KJDD 型）

1. `00_テスト計画書.md` のバージョンと `確認事項一覧` を読む  
2. 変更依頼の章だけ充足状況を再判定  
3. 矛盾する下位ドキュメント（観点表・設計書）があれば一覧化して確認  
4. 更新履歴に変更理由を1行  

### 「何が必要かだけ知りたい」

Phase A のみ。チェックリストの P0 を「いま優先して決めたいこと」として要約し、質問は最大2個。
