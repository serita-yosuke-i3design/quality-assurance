# テストケース出力テンプレート

## L1 シナリオ（受入テスト観点形式）

```markdown
### {番号}. {大分類名}

- {番号}-{連番}. {検証観点（1文）。期待する業務結果を含む}
```

## L2 機能×観点（骨格）

```markdown
| 機能ID | 機能名 | 観点ID | 観点名 | 検証概要 | 根拠 | 既存ケース |
| --- | --- | --- | --- | --- | --- | --- |
| EC-005 | 注文・決済 | TP-08 | 決済連携 | 3DS 失敗後に届け先が保持される | 受入テスト観点 4-5 | 28 §注文確定>決済失敗 |
```

## L3 ケースブロック

```markdown
### テストケース名：★{大分類}>{中分類}>{小分類}>{操作名}

※ {前提・スコープ・仕様参照を2〜5行}

| 概要 | 内容 |
| --- | --- |
| 機能ID | EC-005 |
| 観点 | TP-08, TP-10 |
| 前提 | {ログイン状態・カート状態} |
| 根拠 | {action-spec パス or 既存ケース} |
```

## L4 手順詳細（結合テスト標準表）

```markdown
| No | 操作（Action） | 期待する動作 | 観点 | 正常系 | 準正常系 | 異常系 |
| --- | --- | --- | --- | --- | --- | --- |
| - | ★{ケース名} | | | | | |
| 1 | {画面/URL} にアクセスする | ・{期待1}<br>・{期待2} | TP-02 画面遷移 | TRUE | FALSE | FALSE |
| 2 | {操作} | ・{API が呼ばれること}<br>・{表示} | TP-05 データ取得・表示 | TRUE | FALSE | FALSE |
```

### L4 追記時のチェックリスト

- [ ] 手順1で独立実行可能な状態まで記載したか
- [ ] 直接 URL とクリック遷移のどちらを検証するか明記したか
- [ ] 準正常系の後に正常復帰手順があるか（該当時）
- [ ] 観点は `観点一覧_共通.md` の TP-xx 表記か
- [ ] 正常系・準正常系・異常系は1つのみ TRUE か
- [ ] API パスは仕様と一致しているか（不一致は `【要仕様確認】`）

## 21_結合テスト項目表 追記行（L2 索引）

```markdown
| IT-{連番} | {機能ID} | {TP-xx} | {テスト内容1行} | {期待結果1行} | |
```
