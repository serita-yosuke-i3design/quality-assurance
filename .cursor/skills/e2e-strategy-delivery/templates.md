```markdown
## 8. Page Object Model（POM）

- **ディレクトリ:** （例: `e2e-appium/pages/` または `screenObjects/`）
- **命名:** 画面名と1対1（例: `LoginPage.ts`）。スペックからは Page のみ経由で操作する。

- **共通 UI:** タブバー等は `components/TabBar.ts` のように分離し、複数 Page から利用
```

## 3. 画面遷移図（Mermaid）— スタンドアロンファイル例

プロジェクトでは `docs/e2e/e2e-screen-flows.md` などに置く。**以下はコピー用の骨子**（実際の画面名はアプリに合わせて置換する）。

```markdown
# E2E 用画面遷移図（Mermaid）

| 項目 | 内容 |
|------|------|
| バージョン | 0.1 |
| 最終更新 | YYYY-MM-DD |
| 関連 | [e2e-test-plan.md](./e2e-test-plan.md) / [e2e-test-design.md](./e2e-test-design.md) |

## 運用

- 本ファイルは **アプリ内ナビゲーションの共有の正** とする。変更は機能 PR と同時に更新する。
- E2E のシナリオ追加時は、**図上にパスが存在すること**を確認してから計画書・スペックを更新する。

## クリティカルパス（例）

（flowchart / stateDiagram 等、チームで読みやすい記法を選ぶ）

## シナリオ対応表（図のパス → 計画書）

| 計画書シナリオID | 図上のパス（起点→終点） | 備考 |
|------------------|-------------------------|------|
| 1 | Launch → 主要シェル | スモーク |
| | | |

## Mermaid から E2E シナリオを切り出す手順

1. 図で **起点から終点までの辺の列** を1本ずつ取り出す（分岐ごとに別シナリオ候補）。
2. 各列について Given（前提）/ When（Page メソッドの列）/ Then（到達状態と期待）を書く。
3. [e2e-test-plan.md](./e2e-test-plan.md) のシナリオ ID・優先度と突合し、不足があれば **先に計画書を改訂**する。
4. [e2e-test-design.md](./e2e-test-design.md) の POM 規約に従い、ノード→Page・辺→メソッドとして実装する。

## 改訂履歴

| 日付 | 変更内容 |
|------|----------|
| | |
```
