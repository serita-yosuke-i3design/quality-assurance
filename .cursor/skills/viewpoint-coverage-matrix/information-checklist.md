# 機能×観点カバレッジ表 — 必要情報チェックリスト

Phase A では、ドキュメントごとに **作成可否シグナル** を付ける。チェックリスト項目はその判定の根拠に使う。

| シグナル | 意味 |
| --- | --- |
| 🟢 作成可 | Skill に沿い期待品質の出力が可能 |
| 🟡 条件付き作成可 | 作成可能だが条件未解消だと精度低下または既知ギャップ |
| 🔴 作成不可 | 前提不足。Phase B 禁止 |

項目の充足は **確定 / 一部 / 未** でもメモ可（作成可否判定の内部メモ）。未決は会話で確認し、合意後に md へ反映する。

**優先度**

- **P0**: これが無いと表の骨格が立たない
- **P1**: マトリクスの実用性に直結
- **P2**: 後追いでよい（`【要確認】` 可）

## 壁打ちシナリオ例

### 新規プロジェクト（表が無い）

1. P0: 系統分割・機能ID 規則・観点セット  
2. P0: ◎○△− のルール  
3. P1: (n) を載せるか・正ソース  
4. Phase B: 観点一覧_共通 → 索引 → 1系統のマトリクス骨格  
5. P1: 02 評価表の要否  

### 既存表の改訂（KJDD 型）

1. 01a/b/c のバージョン・更新履歴を読む  
2. 変更依頼（機能追加・観点変更・(n) 再集計）の影響範囲を列挙  
3. 5点整合（索引・01x・共通・02・ケース）のうちズレを確認  
4. 部分ドラフト → 連動ファイル一覧をユーザーに提示  

### 「可否だけ知りたい」

Phase A のみ。P0 を「いま優先して決めたいこと」として要約。質問は最大2個。

### メンテのみ（ケース追加後）

1. 正ソースの diff またはユーザー申告を確認  
2. (n) 再集計の要否を判断  
3. 02 の「無→有」更新が必要な行を列挙（全文は了承後）
