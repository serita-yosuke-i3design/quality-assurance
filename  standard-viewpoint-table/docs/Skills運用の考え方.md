# 標準観点表 × Cursor Skills 運用の考え方

## 1. 「スキルに観点を全部含める」案の説明

**意味**: 観点の中身（各 `viewpoints/**/*.md` の表）を、Skill 用ディレクトリ内の **reference 用ファイルにコピーして持っておく**構成。

| 方式 | 観点の置き場所 | メリット | デメリット |
|------|----------------|----------|------------|
| **今回採用（索引のみ）** | 従来どおり `viewpoints/` のみ。Skill は「どのファイルを読むか」の索引だけ持つ | 正が1箇所。観点を直したら即反映。Skill のメンテは索引だけ | 標準観点リポジトリがワークスペースにないと使えない |
| **全部含める** | Skill 内に `reference/04-登録・編集-共通.md` のように観点を複製 | リポジトリを開いていなくても Skill 単体で動く | 観点を更新するたびに **Skill 側の reference も同じ内容で更新する必要**があり、正が「viewpoints/ と Skill の2箇所」になる |

**結論**: 社内で「標準観点の正はこのリポジトリだけ」にしたいなら、**索引のみの Skill** にしておき、観点の中身は `viewpoints/` のみに置く運用がよい。「全部含める」は、リポジトリをクローンしない環境でも同じ観点で揃えたい場合の代替案として理解すれば十分です。

## 2. テストケースで追加された観点 → 標準観点を更新する設計

「手動で追加した観点を、自動で standard-viewpoint に反映」を **完全自動** にするには、テストケースの保存場所（TestRail・Spreadsheet・Markdown など）と standard-viewpoint リポジトリの連携が必要で、環境依存が大きいです。ここでは **半自動〜自動に近い運用** を想定した設計にします。

### 2.1 前提

- テストケース作成時に「標準観点にはないが、このプロジェクトで追加した観点」が出てくる。
- そのうち社内で再利用したいものだけを、標準観点表に取り込みたい。
- 標準観点表の **書き方（表形式・編集履歴）** は現状のスタイルを崩さない。

### 2.2 推奨フロー（3段階）

| 段階 | やること | 役割 |
|------|----------|------|
| **A. 出力を揃える** | テストケース作成・レビュー時に「追加した観点」を、**決まったフォーマット**で出力する（Skill で Agent に指示）。 | Agent / 作成者 |
| **B. 候補を集約する** | そのフォーマットを `proposals/` や Issue に貼り付け、必要なら「学び元プロジェクト」「備考」を追記する。 | 担当者 / レビュアー |
| **C. 本反映する** | 合意した候補を、該当する `viewpoints/{機能}/{共通|web|アプリ}.md` の観点一覧＋編集履歴に **手動で反映**（またはスクリプトで差分を生成して人が確認）。 | 標準観点のオーナー |

「自動」にできるのは主に **A**（フォーマットを揃えて出すこと）と、**C** のうち「提案差分の markdown を生成するスクリプト」まで。**B の判断（採用するか）と C の最終反映**は人の判断を入れる想定です。

### 2.3 何を「自動」にできるか

- **Skill による自動化**:  
  - 「テストケース作成時に標準観点を参照する」  
  - 「標準にない観点を追加した場合、**追加観点提案**を決まった形式で出力する」
- **スクリプトでできること（将来）**:  
  - 提案用 markdown（例: `proposals/追加観点候補.md`）や JSON を入力に、  
    `viewpoints/` 用の「観点行」＋「編集履歴行」の差分テキストを生成する。  
  - 反映は人がファイルに追記 or PR で行う。

これにより「テストケースで手動追加した観点」が、形式を崩さずに標準観点へ取り込めるようにします。

## 3. 今のスタイルを崩さない運用

- **観点一覧**: 各ファイルとも「機能 or 表示」「テスト観点カテゴリ」「テスト項目（観点）」「確認内容・期待値」の4列の表。
- **編集履歴**: 各ファイル末尾。日付・変更種別・対象観点（テスト項目）・学び元プロジェクト（代表）・備考。
- **共通観点**: 00-共通から移植したブロックはそのまま維持。

Skill やスクリプトは、上記形式を **読み取り・出力の両方** で守るようにします。具体的なタスクは [Skills導入タスク一覧.md](Skills導入タスク一覧.md) に記載しています。
