# 概算ケース数の出し方（標準観点表）

要件が少しずつ決まる段階で、「この機能を入れたらテストはだいたい何本くらい増えそうか」を**素早く**掴むためのルールである。**厳密な件数や工数計算ではない**。スプレッドシートの **X列＝概算ケース数** のように、行ごとに代入して足し合わせられる形を想定する。

## 標準4列との関係

- リポジトリの `viewpoints/**/*.md` の **基本は4列のまま**（機能 or 表示／カテゴリ／項目／確認内容）。
- **概算は5列目**として、プロジェクトのテスト設計シートや複製用テンプレにだけ足してよい。標準 `.md` 全体に5列目を一斉投入するかは、運用で合意してからでよい。
- セルに書くのは **1つの数** ではなく **`式` または `プレースホルダ`** でよい。後から `{{画面数}}` などを具体値に置き換えて合算する。

## X列（概算ケース数）に書く記法

| 記法 | 例 | 意味 |
| --- | --- | --- |
| 定数 | `1` | 正常系など「代表1本で足りる」想定 |
| 定数 | `2` | 代表異常が2本、など |
| プレースホルダ | `{{画面数}}` | プロジェクトで定義した「数える対象」の個数。名前は統一すればよい |
| 式（テキスト） | `2*{{認証要素数}}` | 掛け算は `*` または `×`、どちらかプロジェクトで統一 |
| レンジ | `1〜2` / `3-5` | 仕様未確定時は範囲で置く |

**プレースホルダの命名例**（プロジェクトの用語に合わせてよい）:

- `{{画面数}}` … 認証が必要な画面の数（または同等のルート数）
- `{{認証要素数}}` … ID/パスワードなら `2`、OTP追加なら `3` のように「入力ブロック数」
- `{{バリデーション軸数}}` … 桁数・文字種・必須 など、**独立した検証の軸**の数（仕様が固まるほど精緻化）

## 集計の手順（早さ優先）

1. 要件メモから、各 `{{...}}` に **整数**（またはレンジの中央値）を当てはめる。
2. 各行の式を **掛け算・足し算だけ** で評価する（ネストした式は避け、行を分けてもよい）。
3. **機能単位（例: ログイン）で行を合算**する → 「おおよそのケース本数」の目安。
4. 合算値は **±30〜50% のブレ**を前提にする（詳細仕様・回帰方針で増減するため）。

## 「1観点行」と「本数」の対応ルール（すり合わせ用）

- **1行＝テスト観点1つ**（標準表の粒度）。X列は **その観点をケースに落としたときの「最低限の本数の目安」** でよい。パラメタライズで1本にまとめる場合は、式を `1` に寄せてメモで補足する。
- **画面数依存**の観点（ガード・直URL・セッション切れ後の遷移など）は、**`{{認証要画面数}}` や `{{認証要URL数}}`** のように **数え方を1つ決めて**プレースホルダに寄せる。同じ画面を別観点行で二重に `{{画面数}}` しないかだけ、合算時に注意する。

## S/M/L（重さ）との併用

- **S/M/L**: 優先度・リスクの**相対**の目安。
- **概算ケース数**: 代入後の**規模感**（絶対寄り）。
- 両方あっても矛盾しない。本数の見積もりだけが欲しいときは X列（式）を主に使う。

## ログインまわりの記載例（テンプレ）

プロジェクトのシートにコピーするときの「式の例」。数値はあくまで例。

| 観点のイメージ | X列（概算）の例 | メモ |
| --- | --- | --- |
| 正しい情報でログインできる | `1` | 代表正常1本 |
| 誤り・欠損で拒否される | `2*{{認証要素数}}` | 「片方だけ正」等の最低保障。ID/PWなら `*2` で4本、など調整可 |
| 入力チェック（桁・文字種・必須） | `{{バリデーション軸数}}*2` | 軸ごとに境界＋代表異常の粗い倍率。仕様が厚いほど係数を上げる |
| ログイン後の初期遷移 | `1` | 入口が1系統なら1 |
| 認証要リソースへの未ログインアクセス | `{{認証要URL数}}` | Webの直叩き。画面＝URL で数える |
| セッション切れ後のリダイレクト | `1` | 仕様が「全画面共通」なら1でまとめる運用も可 |
| アプリの再起動・復帰で状態維持 | `1〜2` | スモークと回帰の切り分けはプロジェクト次第 |

**ログイン機能**と**ログイン状態管理（ガード）**は、要件上は別ブロックになりやすい。見積もりも **ブロックごとに小計** してから足すと、後から「画面数が増えた」ときの差分が追いやすい。

## 編集時

新しい観点行を標準表に追加するとき、概算の考え方が分かりにくければ **確認内容の末尾に括弧で「概算: 式の意図」** を1行足してよい（任意）。または本ドキュメントに **ログイン以外の機能の例** を追記していく。
