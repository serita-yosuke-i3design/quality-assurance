# テストレベル指針（単体と結合以降）

観点によっては **単体テストで分岐・ロジックを主に担保できる**ものと、**実環境（実API・実画面・実ネットワーク）に依存し結合テスト以降でしか担保しきれない**ものが混在する。  
仕様・テスト設計で「どのレベルで何を必須とするか」を明示しておかないと、単体で十分なのに結合で重複したり、逆に結合しか見ていないために漏れが出る。

## 列の意味（テストケース管理ツールの「テストレベル」列との対応イメージ）

テストケース票などに **テスト実施レベル** を表す列（例: スプレッドシートの **X列** = `実施レベル`）がある場合、次のルールで **ケース行** を振り分ける。

| 観点の扱い | X列（実施レベル）に書く値のイメージ | 説明 |
| --- | --- | --- |
| 単体で主担保できる（十分実施済み） | `結合`（または `E2E`）のみ | 結合以降用のケースだけを持ち、単体用の重複ケースは切らない。 |
| 単体だけでは不足しうる | `単体` と `結合` の **両方** | 単体用ケースと結合用ケースを別行で持つ。 |

プロジェクトの用語に合わせて X列の取りうる値（`単体` / `結合` / `E2E` 等）は置き換えてよい。重要なのは **「単体十分なら結合側の詳細ケースを省略してよい観点」** と **「結合必須の観点」** の区別がテスト設計書に残ることである。

| パターン | 単体テスト | 結合テスト以降（結合・E2E 等） |
| --- | --- | --- |
| **A: 単体で主担保できる** | ケースを **単体に載せる**（分岐・モックで網羅）。 | **結合では載せない（省略可）**。リリーススモークや回帰方針で別途1本だけ触れるのは可。 |
| **B: 単体だけでは不足しうる** | 分岐の **単体は実施推奨**（モックで可能な範囲）。 | **結合以降でも必ずケースを載せる**（実通信・実UI・永続化など）。 |

運用メモ:

- 「A で単体が **十分に実施されている**」= レビューでカバレッジ・モックの妥当性が合意済みであること。未整備ならパターン B と同扱いに戻す。
- 結合で「省略可」でも、**プロダクト方針で E2E スモーク必須**の場合は、そのスモークは本指針の「省略」とは別管理でよい。

## 記載の置き場所

- 該当する観点を持つ `viewpoints/**/*.md` に、**該当する観点行の直後**に `### テストレベル（単体／結合以降）` として **サブ表** を置く。  
- メインの観点表は従来どおり **4列のまま** とし、テストレベルはサブ表で観点名と対応づける。Markdown の都合で、サブ表を挟むと **観点一覧が「続き」表に分かれる**ことがある（`（観点一覧の続き）` 見出しの下にヘッダ行を再度置く）。

## 入力補助（郵便番号）— 標準的な振り分け

以下は `04-登録・編集` および `16-情報変更` の郵便番号関連3観点に対する **推奨** である。プロダクトのテストピラミッドに合わせて調整してよい。

| テスト項目（観点） | 単体テスト | 結合テスト以降 |
| --- | --- | --- |
| 郵便番号入力補助（未登録7桁） | **要**。7桁確定後に API 応答が 0 件・該当なし相当のときのメッセージ、フィールド状態、送信可否の **分岐** をモック等で担保。 | **単体で主担保済みなら省略可**。実マスタ／実APIとの差分、表示の見た目・アクセシビリティが論点なら結合で **最低限** 追加。 |
| 郵便番号入力補助（API異常時） | **要**。HTTP エラー、タイムアウト、想定外スキーマ、空結果など **異常系分岐** をモックで担保。 | **必須**。実ネットワーク・ゲートウェイ・TLS・実サービスのタイムアウト境界は単体では再現しきれないため、結合以降でケースを持つ。 |
| 郵便番号・住所の手入力保存 | **要**。「補助失敗・未検証でも保存可能」など **ビジネスルールとバリデーション連携** を単体で担保。 | **必須**。画面操作から保存 API・DB 反映までの **一連の経路** は結合（または E2E）で担保。 |

## 編集時

新たに「単体と結合の役割が割れる」観点を追加するときは、本ドキュメントに行を足すか、当該 `viewpoints/` ファイルのサブ表を更新し、編集履歴に記載する。
